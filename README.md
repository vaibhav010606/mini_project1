# Multimodal Crowd Anomaly & Stampede-Risk Detection over 5G

AI/ML project: detect crowd danger from **CCTV video** and **5G network data** of the same event with one
**combined model**, and compare **edge (MEC) vs cloud** processing over 5G with **network slicing** and an
**ML offloading decision**.

- Report: `report/report.pdf`
- Slides: `report/slides.pdf`
- All graphs: `results/figures/`
- All numbers: `results/*.json`

## Requirements

Python 3.10+ (tested with 3.13), Node.js 18+ for the web app, and Git.
An NVIDIA GPU is optional but makes training ~10× faster. Microsoft Edge or Google Chrome is used to make the PDFs.

```powershell
git clone https://github.com/vaibhav010606/mini_project1.git
cd mini_project1
pip install -r requirements.txt
```

For GPU training, install the CUDA build of PyTorch from https://pytorch.org/get-started/locally/ **before**
`pip install -r requirements.txt` (otherwise the CPU build is installed).

All trained models are included in `results/models/`, so the web app works right after installing; the dataset is
only needed to retrain (see below).

## Dataset

UCSD Anomaly Detection Dataset (Ped2), from http://www.svcl.ucsd.edu/projects/anomaly/ (≈ 706 MB).
Extract it so this folder exists:

```
data/UCSD_Anomaly_Dataset.v1p2/UCSDped2/
```

The 5G network data and the joint video + 5G data are generated by the simulator (no download needed).

## The models

| Model | Input | Data | Result |
|---|---|---|---|
| Model 1: video anomaly (v2 future-frame prediction U-Net) | CCTV video | UCSD Ped2 (real) | AUC 0.974 |
| Model 2: crowd risk from 5G (XGBoost) | 5G network features | simulated 5G crowds | 98.2% accuracy |
| **Combined video + 5G model** | the last 4 CCTV frames **and** the last 30 s of 5G data of the **same event** | joint simulated events | macro-F1 0.950 (video only 0.823, 5G only 0.924) |
| ML offloading decision (XGBoost) | network situation | simulated 5G MEC | right choice 94% of the time |

### Combined video + 5G model

`joint/generate.py` runs the 5G crowd simulator once per event and produces **both**:
- the 5G network features from the people's phones, and
- an overhead CCTV video (96×96, 1 frame/s) of an 80 m × 80 m part of the venue, rendered from the **same** people.

It also creates hard cases on purpose: night video, the danger outside the camera's view, and few phones visible to the operator.
`joint/train.py` trains a video CNN + 5G branch together (plus video-only and 5G-only versions for comparison) and reports
results per condition in `results/joint_metrics.json`.

```powershell
python joint/generate.py --episodes 100   # 300 events, ~2 min, data/joint_dataset.npz (500 MB)
python joint/train.py                     # ~2.5 min on a GPU
```

## Run everything

```powershell
python run_all.py               # full pipeline, about 55-60 min with a GPU
python run_all.py --skip-train  # reuse trained models and data, regenerate results, figures, report
```

## Try it on a video

```powershell
python detect.py --video my_crowd_video.mp4
python detect.py --video data/UCSD_Anomaly_Dataset.v1p2/UCSDped2/Test/Test004 --mode ae
```

- `ae` mode: trained video model. Accurate on UCSD-style scenes; other scenes need their own normal training video.
- `motion` mode: optical-flow crowd-motion detector for any fixed camera (alerts on sudden running / scattering).
- Output in `results/detect/`: annotated video, score graph, JSON with alert times.
- Sample videos to try are in `samples/` (`python samples/make_samples.py`, `python samples/make_stampede.py`).

## Web app (React frontend + FastAPI backend)

Five pages:
- **Smart mall 3D**: 3-floor 3D digital twin of the mall (42 shops, atrium, escalators, lifts) with floor views,
  exploded view, camera presets and shop details.
- **CCTV wall**: control-room view of 12 simulated live camera feeds (4 per floor); crowds build up and clear at the
  entrance, food court, escalators and cinema, with BUSY / CROWDED alerts and an alert log.
- **Combined (video + 5G)**: one event, CCTV video and 5G density map side by side, verdicts of the combined, video-only and
  5G-only models every second, with night and few-phones switches.
- **Video detection**: upload or pick a video.
- **5G crowd monitor**: animated density map + Model 2.

The edge vs cloud and slicing results are in the report and slides (they were removed from the web app).

Needs Node.js 18+ in addition to the Python packages above. Install the frontend packages once:

```powershell
cd frontend
npm install
```

Then open **two** terminals.

Terminal 1, backend (from the `crowd-anomaly-5g` folder):
```powershell
python -m uvicorn api.server:app --port 8000
```

Terminal 2, frontend (from the `crowd-anomaly-5g/frontend` folder):
```powershell
npm run dev
```

Open http://localhost:5173 in a browser. Keep both terminals running while you use the app; closing the backend
terminal makes the pages show "502 Bad Gateway".

The app opens with a **demo login screen**. The demo account is shown on that screen (and set in
`frontend/src/auth.js`); the **Use demo** button fills it in. This is for presentations only: there are no real
accounts, nothing is sent to a server, and the login lasts until the browser tab is closed or you click **Log out**.

| Part | File |
|---|---|
| API server (5 endpoints, serves `results/` files) | `api/server.py` |
| Workers that run PyTorch in a separate process (so CUDA and XGBoost never share one Python process) | `api/detect_worker.py`, `api/combined_worker.py` |
| Pages | `frontend/src/pages/*.jsx` |

## Project structure

| Folder / file | What it does |
|---|---|
| `video_model/` | Model 1: dataset loading, v1 autoencoders (big + lightweight student), v2 future-frame prediction U-Net (`predict_model.py`, final model), evaluation (AUC), speed benchmark |
| `network_model/` | 5G crowd simulator, Model 2 (rule / XGBoost / LSTM), density heatmaps |
| `joint/` | Joint video + 5G dataset of the same events, and the combined model |
| `fusion/` | Earlier baseline: score-level fusion of separately trained models |
| `edge_cloud/` | 5G MEC edge vs cloud simulation with URLLC slicing, ML offloading model |
| `detect.py` | Upload-a-video demo tool (command line) |
| `samples/` | Sample videos and the scripts that make them |
| `api/`, `frontend/` | Web app: FastAPI backend and React frontend |
| `report/` | Builds `report.pdf` and `slides.pdf` from the results |
| `run_all.py` | Runs every step in order |

## Notes and limitations

- The 5G network side (crowd sensing, MEC, slicing) is simulated in Python using the same concepts as Simu5G
  (gNB cells, UEs, 3GPP path loss, handovers, MEC host, URLLC/eMBB slices). Porting to Simu5G/OMNeT++ is future work.
- The combined model is trained and tested on simulated events: its CCTV video is rendered from simulated people, not real
  footage. Real paired CCTV + operator data would be needed to confirm the numbers.
- The night results of the combined model rest on only 7 test events.
- Only zone-level counts are used from the network: no individual is tracked.
